P1. The spawnSync surface — ONE mechanism, named
================================================================

Measured already (oracle side only, node v25.9.0, this Windows host):

  spawnSync("/bin/sh", ...) on win32 cannot spawn. Node's result is
      status: null, signal: null, pid: 0, output: null,
      stdout: undefined, stderr: undefined, error: Error("spawnSync
      /bin/sh ENOENT")
  i.e. on a SPAWN FAILURE Node leaves stdout/stderr ABSENT (undefined),
  not "".

PREDICTION P1a: scriptc's runtime models a failed spawn with EMPTY
STRINGS ("") for stdout/stderr rather than undefined/absent. Named
sites I expect to carry it:
    packages/runtime/src/scr_child.c            (the spawnSync impl)
    packages/compiler/src/frontend/lowering/lower-calls.ts  (result
        record shape / slot types for the spawnSync return)
    packages/compiler/src/frontend/lowering/surfaces.ts     (the
        child_process surface declaration)

PREDICTION P1b: this single difference explains ALL THREE rows,
because on this host every /bin/* spawn fails:
  * 1360-spawn-sync.ts        — Node THROWS at line 29
        (killed.stdout.length, stdout===undefined ->
         "TypeError: Cannot read properties of undefined (reading
         'length')"), exit 1. scriptc, answering "", prints
        "true 0 0" and keeps going. Divergence = stdout + exit code.
  * 1482-spawnsync-error.ts   — Node THROWS at line 24
        (ok.stdout.trim()), exit 1. Same cause.
  * 1537-os-release-spawnsync-stdio.ts — Node does NOT throw
        (it only JSON.stringify's stdout) and prints
        "-1 undefined" twice. scriptc will print '-1 ""' twice.
        Divergence = stdout only, no crash.
  So the SAME single mechanism produces two crash-shaped rows and one
  plain-text row. That is why it was never grouped: the failure text
  looks different in 1537.

PREDICTION P1c: therefore it is ONE fix, not three — make the
spawnSync result's stdout/stderr ABSENT when the spawn itself failed
(error set / pid 0), matching Node exactly. 1537 additionally needs
os.release() to be byte-exact ("10.0.26200" on this host); I predict
that half already works, because os.release() is not part of the
spawn surface.

PREDICTION P1d (a real risk I am recording so it cannot be
retro-fitted): the three fixtures may be POSIX-SHAPED FIXTURES, i.e.
their author assumed /bin/sh exists. If so the honest classification
