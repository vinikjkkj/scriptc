    share of each fiber run's OWN transient: 43.40%   43.71%   43.58%

    THE 1,371 B/task FIGURE IS NOT A MEASUREMENT OF THIS CLASS.
    tests/perf/pagecensus/evidence-fr2/PERTASK.txt, lines 2-3 and 10, verbatim:
      "Denominator: 20207 stacks on f1 minus 17 on v3 = 20190 tasks, both LOW mode."
      "This is a DIFFERENCE per task, not a measurement of one task in isolation:"
      "  CRT heap                     26.390         1371     6.8%"
    So 1371 = 26.39 MiB / 20,190 = 1371 B -- a DIVISION over the WHOLE CRT
    heap lane delta, every size class folded together, taken on a DIFFERENT
    instrument (the pagecensus VirtualQuery walk), a DIFFERENT pair of binaries
    and a DIFFERENT tree. Category (b)+(c) of the three asked for: DERIVED BY
    DIVISION, and an AVERAGE THAT INCLUDES OTHER CLASSES.

    AND THAT IS WHY THE BYTE MATCH CANNOT CONFIRM ANYTHING. On the fiber arm
    measured here the 1,328 class alone is 29,307,077 B mean = 27.949 MiB,
    which is 105.9% of the 27,671,921 B that PERTASK.txt divides -- it OVERSHOOTS
    that total, which is itself the proof that the two are not the same
    measurement (different tree, different binaries, different instrument).
    What survives the mismatch is the only thing needed: ON ANY OF THESE
    DENOMINATORS THE 1,328 CLASS IS ESSENTIALLY THE WHOLE CRT-HEAP LANE TERM.
    And if one class is essentially the whole sum, the sum over a count MUST
    land near that class's block size. 1,328 against 1,371 is arithmetically
    forced, not independent. CIRCULAR -- the byte half cannot be affirmed.

    THE NON-CIRCULAR HALF IS THE BLOCK COUNT, AND IT IS MATCHED BY MODE.
    pagecensus/evidence-fr2/manifest.txt line 37 reads
      "f1   fiber      low      446.844          446.164    99.85%    61403   20207"
    -- 20,207 STACK REGIONS, fiber, LOW mode, counted by a VirtualQuery walk that
    never touches the heap. The two LOW-mode fiber runs here read 20,203 blocks of
    1,328 at the heap peak. That is 4 apart, 0.020%, from a DIFFERENT
    instrument on a DIFFERENT tree. This is a genuine independent corroboration,
    and it is a COUNT -- it borrows no byte figure from anywhere.
      f1   fiber LOW   stacks (VirtualQuery)   20,207
      p2   fiber LOW   1,328 blocks (HeapWalk) 20,203
      p3   fiber LOW   1,328 blocks (HeapWalk) 20,203
      p6   fiber HIGH  1,328 blocks (HeapWalk) 24,242   -- no HIGH-mode fiber stack count exists
    I RETRACT, BEFORE WRITING IT DOWN, THE READING THAT p6 REFUTES THE LAW. The
    population that matters is tasks SUSPENDED AT THE PEAK INSTANT, which is not
    the dial: p6 is the HIGH-mode run (section 3), and in the HIGH mode one more
    history-sync chunk is in flight. 4,039 extra blocks for one extra chunk.
    manifest.txt commits no HIGH-mode FIBER row (v1 is high-mode STACKLESS), so
    there is nothing to check p6 against. UNTESTED, not refuted.

    VERDICT ON THE HYPOTHESIS, IN TWO HALVES:
      (i)  "one 1,328 B block per parked task": SUPPORTED, by a count, in LOW
           mode, to 0.020% against an independent instrument. n = 2 LOW-mode runs,
           and both read the IDENTICAL 20,203 -- which is itself worth noting as
           a suspiciously exact repeat and is reported, not explained.
      (ii) "1,328 and 1,371 are the same number by another route": CIRCULAR, and
           it is not a second route. 1,371 is a whole-heap lane delta that THIS
           class accounts for in full, divided by a count that is THIS class's
           block count to 0.02%. It is this class's block size recomputed the
           long way. The true per-block size is 1360 B MEASURED (1,328 request
           + 32 overhead), and 1,371 is DERIVED, so the 11 B between them is a
           property of the two denominators, not a finding about the program.

=== 8. WHAT THIS CANNOT SAY ===
    * The ALLOCATION SITE of the 1,048,576 / 934,576 pair is still unnamed.
      PEAK-OCCUPANT.md section 4 says so and nothing here changes it: a size, a
      count and a mode is what a HeapWalk can be asked for.
    * FLOW vs RETENTION is not separated. The 1,048,576 / 934,576 pair is a
      decode burst caught in the air; the 4,376 class is a cache that is held
      and then released on an idle timer. Both read as "transient" in column (c)
