# Flags and environment variables

The reference for every command-line flag of `scriptc`, every environment variable the compiler, the CLI and the maintainer scripts read, every environment variable a compiled program's runtime reads, and the compile-time `-D` knobs of the runtime. It is checked against the source: `tests/harness/flags-env-doc.test.ts` extracts the same inventory mechanically (the keys of the CLI's `parseArgs` options, every `process.env` read, every `getenv` in the runtime, every `#ifndef SCR_*` default) and fails, naming the item, when a name is missing from this file or when this file lists a name the code no longer has. Adding a flag or a variable therefore means adding its row here.

Conventions used in the tables:

- **Class**: *user-facing* (meant to be set by people who build or run programs), *tuning knob* (changes a trade-off; the default is the measured choice), *debug/lab* (diagnostics, A/B switches and measurement seams; no stability promise), *internal test/CI* (read by the test harness, CI workflows and maintainer scripts), and *Node-standard* (an environment variable Node itself defines; a compiled program **behaves like Node**).
- **Default / accepted** states what the code accepts. Where a variable is only a switch the code tests for presence, that is said. Where the source gives no description of a variable, the row says so and shows the line that reads it instead of guessing a meaning.
- Rows marked with a description starting `[source comment]` were extracted from the comment that names the variable in the source; they were not re-derived, and they can be longer in the code. The rows without curated text are the debug and ablation switches of the compiler (`*_WHY`, `*_OFF`, `*_TRACE`, `*_CENSUS`): each enables or disables one lowering arm or one diagnostic print and exists so one binary can emit both sides of an A/B.

## Command line

`scriptc <command> [options]`. Boolean flags also accept a `--no-<flag>` spelling (the CLI runs `node:util` `parseArgs` with negation allowed); the two that matter, `--no-keep-c` and `--no-layout-order`, have rows of their own.

### Commands

| Command | Meaning |
|---|---|
| `build` | `scriptc build <file.ts\|.js> [options]`: compile to a native executable (`--lib` for library mode). |
| `run` | `scriptc run <file.ts\|.js> [options]`: compile and run. |
| `coverage` | `scriptc coverage <file.ts\|.js> [--dynamic]`: how much of the program compiles statically, and why not; with `--dynamic`, what a dynamic build compiles and what still blocks it. |
| `layout-order` | `scriptc layout-order <exe> <profile> [-o order.txt]`: turn a layout profile recorded by a `--layout-profile` binary into an order file (stdout without `-o`). |

### Flags

| Flag | Value | What it does | Default |
|---|---|---|---|
| `--out`, `-o` | string | Output executable path. | `.scriptc/<name>` next to the input. |
| `--backend` | `llvm` or `c` | Code generator. `llvm` is the default and the output that ships; `c` emits readable C for inspecting the compiler's output, and program behavior is identical either way. A program outside the LLVM tier still builds on the default lane (it emits C for it and prints a one-line stderr note naming the construct), while an explicit `--backend llvm` fails with that construct named. | unset = the default lane (LLVM with the transparent C fallback). |
| `--from-c` | boolean | Treat the input as a C (or `.ll`) file instead of TypeScript/JavaScript: toolchain plumbing and debugging. Cannot be combined with `--ffi`. | off |
| `--from-kept` | boolean | Treat the input as the `<stem>.keep.json` a build writes next to its kept program translation unit, and re-run only clang and the link from that directory (split parts and link gates included) with whatever C flags the environment gives (`SCRIPTC_PROF_CFLAGS`, `SCRIPTC_OPT_LEVEL`, ...) and `--sanitize` / `--layout-profile`. Anything that changes the emitted program (`--layout-order`, `--backend`, `--npm-static`, an emission switch) needs a real build; `--ffi` cannot be combined with it. | off |
| `--keep-c` | boolean | Keep the generated program translation unit next to the executable (the `.ll` under the LLVM backend, the `.c` under `--backend c` or when the build fell back). | on. `--no-keep-c` deletes it after compiling. |
| `--no-keep-c` | boolean | Delete the generated program translation unit after compiling. | off |
| `--emit-ir` | boolean | Also write the IR as JSON next to the executable. | off |
| `--sanitize` | boolean | Build with AddressSanitizer plus the runtime's reference-count audit. | off |
| `--layout-profile` | boolean | Build an instrumented binary that records which functions run; the file is written to `$SCR_LAYOUT_PROFILE_OUT` at exit, and `SIGUSR1` starts a new epoch (send it when startup is over). Feed the file to `scriptc layout-order <exe> <profile> -o order.txt`. | off |
| `--layout-order` | path | Write the program's functions in the order the file lists (steady set first, then other executed code, then startup-only; names not listed go last, unknown names are ignored). A build also picks up `<entry>.scriptc-order.txt` beside the entry by itself and prints one line saying so; this flag names another file. | unset (the automatic `<entry>.scriptc-order.txt`, if present). |
| `--no-layout-order` | boolean | Do not pick up `<entry>.scriptc-order.txt` automatically. | off |
| `--pgo` | boolean | Profile-guided layout in one command: an instrumented build, one profiling run, the order file, and the final ordered binary. Requires `--pgo-run` and either `--pgo-signal` or `--pgo-no-signal`. Writes `<entry>.scriptc-order.txt` (check it in) or the path `--layout-order-out` names. Linux and macOS only (it needs `SIGUSR1`). | off |
| `--pgo-run` | string (a command) | The profiling run. It EXECUTES the program you name; it is never inferred and never run by a normal build. The command is split into words (whitespace; single and double quotes; a backslash escapes the next character) and started without a shell, so pipes, redirections, globs and `$VARIABLES` are not interpreted (name a shell yourself: `--pgo-run "sh -c '...'"`). `{bin}` in any word is replaced by the instrumented binary, which is also exported as `$SCR_PGO_BIN`. The program must exit (or be terminated: `SIGTERM` keeps the profile). | required with `--pgo`. |
| `--pgo-signal` | regex | Send the epoch signal (`SIGUSR1`) to the profiled program when a line of the command's output first matches the regex: put it where startup is over and the real work begins. The run fails if it never matches. | none; `--pgo` needs this or `--pgo-no-signal`. |
| `--pgo-no-signal` | boolean | Profile without an epoch signal: one epoch, so the order is first-reached order only (weaker for servers, whose steady-state code is what an epoch signal separates from startup). | off |
| `--pgo-timeout` | seconds (positive number) | Stop the profiling run after this long. | 120 |
| `--layout-order-out` | path | Where `--pgo` writes the order file. | `<entry>.scriptc-order.txt`. |
| `--dynamic` | boolean | Embed the dynamic engine (about 620 KB); static stays the default. With `coverage`, report what a `--dynamic` build compiles and what still blocks it. | off |
| `--ffi` | file | Bind signature-only TypeScript declarations to native C symbols and link the manifest's archives and libraries. Not available with `--from-c`, `--from-kept` or `build --lib`. | unset |
| `--npm-static` | `pkg[,pkg…]` or `auto`, repeatable | Compile the named npm packages' shipped JavaScript statically as program modules; `auto` opts in every eligible direct import (own `.d.ts`, unminified JS, no build-transform markers). A package the preflight refuses falls back to the island (`--dynamic`) with a coverage-report note. Opt-in and experimental. Not available with `build --lib`. | unset |
| `--provenance-sources` | boolean | EXPERIMENTAL: compile npm dependencies from their provenance-attested source (fetched at the attested commit) as static program modules. A package whose attestation is unusable keeps the island path (a note). A package npm publishes no attestation for (HTTP 404) compiles from its registry tarball, verified against the integrity digest in `pnpm-lock.yaml` or `package-lock.json`; if that digest is missing, the bytes cannot be obtained, or they do not hash to it, the build is refused naming the package. | off |
| `--lib` | boolean | Library mode: `scriptc build --lib --profile <p.json>` compiles the profile's entry module to a linkable static archive (`<name>.lib.a`) exporting the profile-declared C symbols; a profile with a sidecar section also gets the contract sidecar JSON beside the archive. A build mode only (not `run` or `coverage`); takes no input file and none of `--dynamic`, `--backend`, `--npm-static`, `--ffi`. | off |
| `--profile` | path | The library-mode profile JSON. Required with `--lib`. | unset |
| `--help`, `-h` | boolean | Print the usage text and exit 0. Running with no command prints it and exits 1. | off |
| `--version`, `-v` | boolean | Print the installed package version. | off |

## Environment variables read by the compiler, the CLI and the scripts

Columns: name, who reads it, class, what it does, default / accepted.

### User-facing and build tuning

| Name | Read by | Class | What it does | Default / accepted |
|---|---|---|---|---|
| `SCRIPTC_CACHE_DIR` | compiler | tuning knob | Turns on the content-addressed build caches and names their root: whole program binaries (`bin/<key>`) and the compiled runtime objects, so a repeat build of an unchanged program skips clang entirely. Opt-in; the test lanes set it. | unset = no cache. |
| `SCRIPTC_CACHE_MAX_MB` | compiler | tuning knob | Size cap, in megabytes, of the program-binary cache under `SCRIPTC_CACHE_DIR`. | 4096 |
| `SCRIPTC_CC` | compiler | user-facing | Swap the C compiler driver. `zigcc` uses `zig cc` (clang underneath with zig's bundled sysroots: the door to cross-compiling); `clang` is the same as unset. On a Linux host the build adds `-D_GNU_SOURCE` while compiling and `-lm` after all link inputs. | unset = `clang`; `zigcc` or `clang`. |
| `SCRIPTC_CC_JOBS` | compiler | tuning knob | How many compile jobs one build may run at once. | an integer ≥ 1; anything else (or unset) = the CPU count. |
| `SCRIPTC_EMPTY_PIN` | compiler | tuning knob | The empty-collection pin: a fresh `new Map()` the checker leaves `Map<any, any>` takes the `Map<K, V>` its destination declares. | on unless set to `0`. |
| `SCRIPTC_KEEP_PDB` | compiler | tuning knob | Keep the PDB (and with it the debugger's and profiler's symbols) on the zig `x86_64-windows-gnu` lane, at the price of the linker's section collector. | unset, empty or `0` = off; any other value = on. |
| `SCRIPTC_OBJ_CACHE_MAX_MB` | compiler | tuning knob | Size cap, in megabytes, of the runtime-object cache. (No source comment describes it beyond the read.) | 512 |
| `SCRIPTC_OPT_LEVEL` | compiler | tuning knob | The optimization level plain builds compile at. | unset or empty = `-O2`; one of `-O0 -O1 -O2 -O3 -Os -Oz` (anything else is an error). |
| `SCRIPTC_PROVENANCE_CACHE` | compiler | tuning knob | Directory the `--provenance-sources` pipeline caches attested sources in. When it is unset the build notes that the default cache directory is used. | unset = the default cache root. |
| `SCRIPTC_PROVENANCE_MANIFEST` | compiler | tuning knob | Path of a JSON provenance manifest (a `packages` object keyed by package name) read by `--provenance-sources`. | unset or empty = no manifest. |
| `SCRIPTC_STMT_RUN_MIN` | compiler | debug/lab | The statement-run loop pass (`ir/stmt-run-loops.ts`): a run of consecutive dynamic-call statements that differ only in string literals becomes one loop over a constant table. `0` turns the pass off (the A/B arm and the negative control of the rows); an integer N >= 2 sets the minimum run length for every statement size. | unset = 2 for big statements (>= 30 IR nodes), 4 for the others; `0`, or an integer >= 2. |
| `SCRIPTC_STMT_RUN_WHY` | compiler | debug/lab | Prints one `STMTRUN <function> rows N nodes M tables K` line to stderr per loop the statement-run pass builds. | unset = silent; `1`. |
| `SCRIPTC_STABLE_NAMES` | compiler | tuning knob | Stable names for the emitters' counter-named helpers, so unrelated edits do not renumber them. | on unless set to `0`. |
| `SCRIPTC_TARGET` | compiler | user-facing | Cross target triple handed to the zig driver, for example `aarch64-linux-gnu.2.36` or `x86_64-windows-gnu`. Meaningful with `SCRIPTC_CC=zigcc`. | unset = a host-native build. |
| `SCR_LAYOUT_PROFILE_OUT` | CLI | user-facing | Exported by `--pgo` to the profiled program: where the layout profile is written at exit (also read by every `--layout-profile` binary). | set by the CLI; `scr-layout-profile.txt` when a binary runs without it. |
| `SCR_LAYOUT_PROFILE_PID` | CLI | user-facing | Exported by `--pgo` to the profiled program: the file the program writes its process id to, so the CLI can send it the epoch signal even through a wrapper. | set by the CLI. |
| `SCR_PGO_BIN` | CLI | user-facing | Exported by `--pgo` to the profiling command: the path of the instrumented binary (the same text `{bin}` expands to). | set by the CLI. |
| `npm_config_cache` | compiler | user-facing | npm's cache directory, honored by the provenance-tarball fetcher (behaves like npm). | unset = npm's default. |

## How this file stays true

`tests/harness/flags-env-inventory.ts` is the extractor and `tests/harness/flags-env-doc.test.ts` is the check; the test also plants a fake flag, a fake environment read and a fake `getenv` in in-memory copies of the sources and requires itself to fail on each, so an extractor that silently stopped seeing the code cannot pass. The first cell of every table row (all backticked names in it) is what counts as documented. Names the code mentions only in comments or messages are not inventory; the extraction rules are written at the top of the extractor.
